# Aqua Frank Bot — прокачана версія

## Що змінилось порівняно з оригіналом

1. **Секрети винесені з коду.** Токен бота, ID адмін-чату, ID адмінів і назва
   Google-таблиці тепер беруться з файлу `.env`, а не хардкодяться в `.py` —
   можна безпечно тримати код у публічному git-репозиторії.
2. **Кошик і замовлення більше не губляться при перезапуску.** Замість
   `MemoryStorage` (все стиралось при рестарті бота) дані пишуться в SQLite
   (`database.py`): кошики, користувачі, історія замовлень.
3. **"Ввести вручну" тепер реально працює.** Раніше кнопка просто додавала
   1 шт. і писала "функція в розробці". Тепер бот питає число і додає
   вказану кількість (з перевіркою від 1 до 99).
4. **Кошик можна редагувати прямо в чаті**: кнопки ➖/➕ на кожному товарі,
   а не тільки повне видалення.
5. **Оптові знижки** на воду 18,9 л (від 5 і 10 бутлів) — див. `catalog.py`,
   `BULK_DISCOUNTS`.
6. **Історія замовлень для клієнта** — кнопка "📦 Мої замовлення".
7. **Адмін-панель** (`/admin`, доступна лише `ADMIN_USER_IDS`):
   - перегляд нових замовлень з кнопкою "Позначити виконаним";
   - статистика (кількість користувачів, замовлень, виручка);
   - розсилка повідомлення всім користувачам бота.
8. **Валідація вводу**: телефон перевіряється регуляркою, адреса — на
   мінімальну довжину, з можливістю скасувати оформлення в будь-який момент
   кнопкою "❌ Скасувати замовлення".
9. **HTML замість Markdown** для форматування повідомлень — усі
   призвіща/адреси/username екрануються через `html.escape`, тож символи на
   кшталт `<`, `&`, `*` в імені чи адресі клієнта більше не ламають
   повідомлення в адмін-чаті.
10. **Google Sheets більше не критична залежність.** Якщо бібліотек немає,
    немає доступу чи файлу ключа — бот пише попередження в лог і продовжує
    працювати; замовлення вже надійно збережене в SQLite до цього кроку.
11. **Логування в файл** (`bot.log`, з ротацією) окрім консолі — зручно
    дебажити на сервері.
12. **Код розбитий на модулі** (`config`, `catalog`, `database`, `keyboards`,
    `states`, `sheets`, `handlers/*`) замість одного файлу на 400+ рядків —
    легше підтримувати і розширювати.

## Встановлення

```bash
pip install -r requirements.txt
cp .env.example .env
# відредагуйте .env: впишіть BOT_TOKEN, ADMIN_CHAT_ID, ADMIN_USER_IDS
python bot.py
```

## Google Sheets (необов'язково)

Якщо хочете дублювати замовлення в Google Таблицю:
1. Створіть сервісний акаунт у Google Cloud, увімкніть Sheets API та Drive API.
2. Завантажте `credentials.json` у папку бота.
3. Дайте сервісному акаунту доступ на редагування до таблиці `SPREADSHEET_NAME`.

Якщо це не потрібно — просто нічого не робіть, бот пропустить цей крок.

## Структура проєкту

```
aquafrank_bot/
├── bot.py              # точка входу
├── config.py           # читання .env
├── catalog.py           # товари, категорії, знижки
├── database.py          # SQLite: users / cart_items / orders
├── keyboards.py         # усі клавіатури
├── states.py             # FSM стани
├── sheets.py             # безпечна обгортка над Google Sheets
├── handlers/
│   ├── common.py         # /start, інфо, "мої замовлення"
│   ├── catalog.py        # перегляд категорій, кошик: додавання
│   ├── cart.py            # перегляд/редагування кошика
│   ├── checkout.py        # оформлення замовлення (FSM)
│   └── admin.py           # адмін-панель
├── requirements.txt
├── .env.example
└── README.md
```

## Наступні кроки, якщо захочете йти далі

- Додати фото товарів у Telegram file_id замість зовнішніх посилань
  (швидше і надійніше — не залежить від сторонніх серверів).
- Пагінація каталогу, якщо асортимент виросте.
- Вебхуки замість polling для продакшн-деплою (наприклад, на Render/Fly.io).
- Юніт-тести для `catalog.py` (розрахунок знижок) та `database.py`.
